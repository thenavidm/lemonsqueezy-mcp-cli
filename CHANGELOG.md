# Changelog

## 3.0.0, 2026-10-05

Built on [Slipway](https://github.com/thenavidm/slipway) 0.1.20. The 65 tools keep their names and arguments, and every difference below was measured against 2.0.1, the last version on npm, before release.

- **A person approves each confirmed operation over MCP.** All 21 still need confirmation. Claude Code (2.1.246 and later) shows its own prompt, and a client that can show forms asks with an approval form whose one box starts unticked. Approvals are signed, bound to the exact call and work once. Where a client can do neither, the model's `confirm: true` still counts, and `LEMONSQUEEZY_CONFIRM=model` makes it enough everywhere. The refusal and the approval form both say what 2.0 said, that the call may change billing, refund payments, alter licenses/webhooks or save private commerce files, and the audit log records who approved each one.
- **`LEMONSQUEEZY_ALLOW_DESTRUCTIVE=0` still refuses all 21**, confirmed or not, and `LEMONSQUEEZY_READ_ONLY=1` still leaves only the 44 reads.
- **Lemon Squeezy's status picks the exit code.** A request Lemon Squeezy rejects (400 or 422) exits 2 instead of 5, and a removed resource (410) 3 instead of 5. 401 and 403 still exit 4, 404 3, 429 7, a server error 5, and an unknown profile or nothing configured 10. 1 now means an unexpected error.
- **`which <words>` finds a command**, and `agent-context` describes every command, flag and setting as JSON. In Codex 0.159.3, finding the command that cancels a subscription and its flags took a median of 61,907 input tokens over the CLI instead of 61,546 (five runs each): both versions read the general help and one more screen. 2.0.1's runs guessed the command's name and read its help; 3.0.0's asked `which cancel subscription`, whose answer lists it and the two nearest commands, then gives its help. The 361 tokens more are those list lines and 3.0.0's general help, 417 characters longer for `which`, `install`, what each setting is for and the exit codes, which the next request carries.
- **`install <client>`** adds the server to Claude Code, Codex, Claude Desktop, Cursor, VS Code or Gemini CLI in each one's own format, and **`lemonsqueezy-mcp --http`** serves the same tools over Streamable HTTP, on 127.0.0.1:8787 unless told otherwise.
- **A smaller tool list.** Parts that several tools repeated, such as the checkout options, are written once and referred to, so the list is 24,188 o200k tokens instead of 24,974. With every tool loaded, Claude Code 2.1.286 spends 31,362 tokens a message on the list instead of 32,838.
- **Less work to start.** Each input and body schema now compiles on its first use rather than at load, and the entry turns on Node's compile cache. The server spends 195 ms of CPU before its first answer where 2.0.1 spent 360, and answers in 141 ms of wall time instead of 219 (median of 21 runs, taking turns on one Mac). npx installs 10 dependencies instead of 94. A test still compiles every schema.
- **`doctor --network` reads the current user**, as 2.0's did.
- **Docs.** README section 7 has the measured Claude Code and Codex costs, where 2.0 said they were pending, and the exit codes include 1.

### Upgrading

Over MCP, expect an approval prompt or form before any confirmed operation; a headless agent that should run them with `confirm: true` alone needs `LEMONSQUEEZY_CONFIRM=model`. A script that read exit 5 as a rejected request should read 2, and as a removed resource 3. An error is now one JSON object with `error`, Slipway's `code` (`usage`, `refused`, `auth`, `not_found`, `rate_limited`, `api`, `not_configured`) and a `hint`, plus Lemon Squeezy's `status` when it answered; 2.0.1 printed the tool's JSON inside the `error` string. Over MCP, an argument that fails the schema comes back as the MCP SDK's own message, "Input validation error: …", instead of JSON. With `LEMONSQUEEZY_READ_ONLY=1`, a client that calls a hidden tool gets "tool not found" instead of a refusal naming `LEMONSQUEEZY_READ_ONLY`, and that call is not in the audit log; the CLI still names the setting. The audit log's lines gain `confirmed_by`, and each allowed call is followed by a `done` or `failed` line. A script that pipes JSON-RPC into the server must keep stdin open until it reads the answer: the server now stops when its input ends, as the MCP stdio binding asks. `--http` refuses a page from another site unless `LEMONSQUEEZY_HTTP_ALLOWED_ORIGINS` lists it. Some terminal screens grew: the general help by 142 tokens, for `which`, `install`, what each setting is for and the exit codes; the command list by 17; and a missing argument's error by 17, for its code and a hint. Over MCP, Codex printed the same part of the tool list on both sides, 10,319 and 10,304 characters, and the median run read 41,644 input tokens instead of 41,601, within the spread of 2.0.1's own runs, 41,485 to 41,684. `SKILL.md` is 85 tokens longer in Claude Code, because it says how approval works over MCP and how `which` finds a command, and that exit 1 is an unexpected error and 2 also an unknown command or a hidden write.

## 2.0.1, 2026-10-04

- **`npx -y @thenavidm/lemonsqueezy-mcp-cli` starts the MCP server whatever order npm keeps.** npx starts whichever binary the npm registry lists first when they share one file, and the registry does not keep the published order. For this package that happened to be the server; for 23 others it was the CLI. A third binary named after the package, on its own file, now always starts the server, and npx picks it by name.
